ex00

My First Class in Orthodox Canonical Form

A fixed-point class that can only represent 0.0 — on purpose, so the canonical form itself is the whole point of the exercise.

New concepts this exercise introduces
Orthodox Canonical Form
Writing the default constructor, copy constructor, copy assignment operator, and destructor explicitly, instead of relying on the compiler's silent versions.
static const int
One value shared by every Fixed object, not stored per-instance — and one of the few members C++98 lets you initialize directly in the class body.

The pitch

"This class can only represent 0.0 right now, and that's the point — the exercise isn't about the number, it's about proving I can write all four canonical members myself and show, with print statements, exactly which one fires on each line."

Walk the code

Fixed.hpp header

class Fixed {
private:
    int _fixedPoint;                     // storing the raw fixed-point value
    static const int fractionalBits = 8; // shared by all objects, never changes
public:
    Fixed(void);                          // default constructor
    Fixed(const Fixed &other);            // copy constructor
    Fixed &operator=(const Fixed &other); // copy assignment operator
    ~Fixed();                             // destructor
    int getRawBits(void) const;
    void setRawBits(int const raw);
};

One private member, one shared constant, and exactly the four canonical members plus the two functions the subject asks for. fractionalBits is given its value right here in the class body — a special-case exception in C++98 for static const integral types.

Fixed.cpp default constructor

Fixed::Fixed(void) : _fixedPoint(0) {
    std::cout << "Default constructor called" << std::endl;
}

Initializer list sets _fixedPoint to 0 — the only value this class can hold until ex01 adds real conversions. The print statement is the only way to prove, from the program's own output, that this constructor actually ran.

Fixed.cpp copy constructor

Fixed::Fixed(const Fixed &other) : _fixedPoint(other._fixedPoint) {
    std::cout << "Copy constructor called" << std::endl;
}

Builds a brand-new Fixed from an existing one. Only ever runs once, at the exact moment an object like Fixed b(a) is born — never again after that for the same object.

Fixed.cpp copy assignment operator

Fixed &Fixed::operator=(const Fixed &other) {
    std::cout << "Copy assignment operator called" << std::endl;
    if (this == &other) // guard against self-assignment (a = a);
        return *this;
    _fixedPoint = other._fixedPoint;
    return *this;
}

Different job from the copy constructor: this one overwrites an already-existing object's value. Returns Fixed& so assignments can chain (a = b = c;), and guards against a = a; before touching anything.

Fixed.cpp destructor, getRawBits, setRawBits

Fixed::~Fixed() { std::cout << "Destructor called" << std::endl; }

int Fixed::getRawBits(void) const {
    std::cout << "getRawBits member function called" << std::endl;
    return _fixedPoint;
}

void Fixed::setRawBits(int const raw) { _fixedPoint = raw; }

Nothing to release in the destructor — _fixedPoint is a plain int, so an empty body plus the print statement is the fully correct implementation. getRawBits and setRawBits are the only way anything outside the class ever touches _fixedPoint.

main.cpp tests

int main(void) {
    Fixed a;    // default constructor
    Fixed b(a); // copy constructor
    Fixed c;    // default constructor
    c = b;      // copy assignment operator
    std::cout << a.getRawBits() << std::endl;
    std::cout << b.getRawBits() << std::endl;
    std::cout << c.getRawBits() << std::endl;
    return 0;
}

This is the exact test that the subject's own sample output is built around: four lines, four different canonical members firing, in a sequence chosen specifically to make construction and assignment impossible to confuse if the print statements are read carefully.

Questions to expect

Why does Fixed b(a) call the copy constructor and not copy assignment?
b doesn't exist before that line runs. C++ has to build it from scratch using a's value, and building a new object from an existing one is exactly the copy constructor's job. c = b is different: c already exists from the line above, so that's assignment overwriting it, not construction.
Why write all four canonical members if the compiler already generates them for free?
For a class holding one plain int, the compiler's automatic versions would actually work fine. The habit matters because the moment a class owns something like a heap pointer, the automatic version just copies the address, not the data — two objects end up sharing one resource, and the first one destroyed frees memory the second still thinks it owns. Writing all four explicitly now is the discipline that prevents that bug once it's actually possible.
Why is fractionalBits static?
static means there's exactly one copy shared by every Fixed object, not one per instance. It belongs to the class itself, not to any particular object — which makes sense since the scale factor never changes between objects.
Why is the self-assignment guard in operator= there — what would break without it?
For this class specifically, nothing would actually break, since there's no resource to free before copying. I included it anyway because it's the correct shape for a copy assignment operator in general — the day a class does own a resource, skipping that check causes it to free its own data right before trying to read from itself.
Important
Are all four canonical members present, with correct signatures, split between .hpp and .cpp?
Yes — default constructor, copy constructor, copy assignment operator (returning Fixed&), and destructor, all declared in Fixed.hpp and defined in Fixed.cpp, none implemented inline in the header.
Does getRawBits/setRawBits match the exact required signature: int getRawBits(void) const; and void setRawBits(int const raw);?
Yes, both match literally — getRawBits is const since it only reads _fixedPoint, setRawBits is not const since it modifies it.
Do the print statements make it possible to verify, just from the output, which constructor or operator ran on each line of main?
Yes — running main prints Default, Copy constructor, Default, Copy assignment in that exact order, matching the four lines of the test one-to-one.
ex01

Towards a more useful fixed-point number class

Two converting constructors turn an int or float into raw bits; toInt/toFloat undo that; operator<< makes the whole thing printable.

New concepts this exercise introduces
converting constructors
Fixed(const int) and Fixed(const float) — same class, two more entry points, picked automatically based on the argument's type.
bit shift as multiply/divide
num << fractionalBits is exact — same as num × 256, at the bit level, no rounding.
free function operator<<
Can't be a member — Fixed would have to sit on the left of <<, and the whole point is std::cout on the left.

The pitch

"ex00's Fixed could only ever be 0 — this one can represent any int or float. Two new constructors convert into the raw representation, toFloat/toInt convert back out, and operator<< means I can just write std::cout << a instead of manually calling toFloat every time."

Walk the code

Fixed.hpp header, extended

class Fixed {
private:
    int _fixedPoint;
    static const int fractionalBits = 8;
public:
    Fixed(void);
    Fixed(const int num);                 // constructor overloading (for int)
    Fixed(const float num);               // constructor overloading (for float)
    Fixed(const Fixed &other);
    Fixed &operator=(const Fixed &other);
    ~Fixed();
    float toFloat(void) const;
    int toInt(void) const;
    int getRawBits(void) const;
    void setRawBits(int const raw);
};
// An overload of the insertion (<<) operator
std::ostream &operator<<(std::ostream &stream, const Fixed &fix);

Two new constructors sit alongside the default one — constructor overloading, same idea as any other overloaded function, resolved by argument type. operator<< is declared outside the class entirely, right after the closing brace: it's a free function, not a member.

Fixed.cpp int and float constructors

Fixed::Fixed(const int num) : _fixedPoint(num << fractionalBits) {
    std::cout << "Int constructor called" << std::endl;
}
Fixed::Fixed(const float num)
    : _fixedPoint(roundf(num * (1 << fractionalBits))) {
    std::cout << "Float constructor called" << std::endl;
}

The int version shifts — exact, no rounding needed, since an int has no fraction to lose. The float version can't shift a float's bits at all, so it multiplies instead, then rounds to the nearest whole number before that value can be stored in the integer _fixedPoint. roundf is explicitly authorized for exactly this reason.

Fixed.cpp toFloat, toInt

float Fixed::toFloat(void) const {
    return static_cast<float>(_fixedPoint) / (1 << fractionalBits);
}
int Fixed::toInt(void) const { return _fixedPoint >> fractionalBits; }

toInt() mirrors the int constructor exactly — >> undoes <<, and any fractional bits simply fall off the right edge and are gone, no rounding involved. toFloat() can't shift for the same reason the float constructor couldn't, so it divides instead — and the static_cast<float> has to come first, or _fixedPoint / (1 << fractionalBits) would be plain integer division, silently truncating the fraction before a float ever entered the picture.

Fixed.cpp operator<<

// example: stream=std::cout, fix=b (a Fixed holding a raw value of 2560)
//          "b is " << b  ->  fix = b  ->  fix.toFloat() = 2560/256 = 10.0
//          prints: b is 10
std::ostream &operator<<(std::ostream &stream, const Fixed &fix) {
    stream << fix.toFloat();
    return stream;
}

Written using Fixed's own public toFloat(), not by reaching into _fixedPoint directly — there's no friend to fall back on in this module, so the public interface has to already be complete enough on its own. Returns std::ostream& so calls like std::cout << a << b << std::endl; chain correctly.

main.cpp tests

int main(void) {
    Fixed a;               // default constructor
    Fixed const b(10);     // int constructor
    Fixed const c(42.42f); // float constructor
    Fixed const d(b);      // copy constructor
    a = Fixed(1234.4321f); // float ctor builds a temporary, then copy assignment

    std::cout << "a is " << a << std::endl;
    std::cout << "b is " << b << std::endl;
    std::cout << "c is " << c << std::endl;
    std::cout << "d is " << d << std::endl;
    std::cout << "a is " << a.toInt() << " as integer" << std::endl;
    std::cout << "b is " << b.toInt() << " as integer" << std::endl;
    std::cout << "c is " << c.toInt() << " as integer" << std::endl;
    std::cout << "d is " << d.toInt() << " as integer" << std::endl;
    return 0;
}

This is the subject's own example, essentially unchanged. a = Fixed(1234.4321f); is the one line worth pausing on during evaluation: it builds an unnamed temporary via the float constructor, assigns its value into a via copy assignment, then immediately destroys that temporary — three canonical members firing on a single line.

Questions to expect

Why does the int constructor shift, but the float constructor multiply?
Shifting only makes sense for a type whose bits directly encode value times a power of 2 — that's exactly what an int is. A float encodes numbers completely differently (mantissa and exponent), so there's no shift that could scale it. Multiplying by (1 << fractionalBits) achieves the same scaling through arithmetic instead of bit manipulation.
Why is roundf needed for the float constructor but not the int one?
An int has no fractional part to begin with, so shifting it is always exact — nothing to round. A float almost never lands on a whole number after multiplying by 256, so something has to decide how to turn that into the integer _fixedPoint actually stores. roundf picks the nearest whole number instead of silently truncating and always rounding down.
Why can't operator<< be a member function of Fixed?
A member function's implicit first parameter is always the object it's called on — the left-hand side. If operator<< were a member, the only working syntax would be a << std::cout, with Fixed on the left. Since the actual goal is std::cout << a, with the stream on the left, it has to be a free function that takes the stream as its first explicit parameter.
Why does static_cast<float> have to come before the division in toFloat()?
Without it, _fixedPoint / (1 << fractionalBits) is int divided by int — plain integer division, which truncates before a float ever enters the picture. Casting the numerator to float first means the division that follows is real floating-point division, so the fractional part survives.
What actually happens on the line a = Fixed(1234.4321f);?
Fixed(1234.4321f) builds a temporary, unnamed Fixed using the float constructor. a already exists, so a = ... is copy assignment, not construction — the temporary's value gets copied into a. Then, since the temporary has no name and its job is done, it's destroyed immediately, right there on that line.
from the evaluation sheet
Do the int and float constructors produce the correct raw value, verifiable through getRawBits()?
Yes — Fixed(10)'s raw value is 2560 (10 << 8), and Fixed(3.14f)'s raw value is 804 (roundf(3.14 × 256)), both checkable directly with getRawBits().
Is operator<< a free function, not a member, and does it correctly print a float representation?
Yes — declared outside the class in Fixed.hpp, defined outside the class in Fixed.cpp, takes std::ostream& as the first parameter, and prints via toFloat().
Does the test in main cover both constructors, both conversion functions, and printing, matching the subject's own example?
Yes — b and c cover the int and float constructors, d covers the copy constructor, a covers reassignment through a temporary, and every object is printed both via operator<< and via toInt().
