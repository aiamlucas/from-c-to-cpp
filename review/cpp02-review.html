ex00

My First Class in Orthodox Canonical Form

A fixed-point class that can only represent 0.0 — on purpose, so the canonical form itself is the whole point of the exercise.

New concepts this exercise introduces
Orthodox Canonical Form
Writing the default constructor, copy constructor, copy assignment operator, and destructor explicitly, instead of relying on the compiler's silent versions.
static const int
One value shared by every Fixed object, not stored per-instance — and one of the few members C++98 lets you initialize directly in the class body.

The pitch

"This class can only represent 0.0 right now, and that's the point — the exercise isn't about the number, it's about proving I can write all four canonical members myself and show, with print statements, exactly which one fires on each line."

Walk the code

Fixed.hpp header

class Fixed {
private:
    int _fixedPoint;                     // storing the raw fixed-point value
    static const int fractionalBits = 8; // shared by all objects, never changes
public:
    Fixed(void);                          // default constructor
    Fixed(const Fixed &other);            // copy constructor
    Fixed &operator=(const Fixed &other); // copy assignment operator
    ~Fixed();                             // destructor
    int getRawBits(void) const;
    void setRawBits(int const raw);
};

One private member, one shared constant, and exactly the four canonical members plus the two functions the subject asks for. fractionalBits is given its value right here in the class body — a special-case exception in C++98 for static const integral types.

Fixed.cpp default constructor

Fixed::Fixed(void) : _fixedPoint(0) {
    std::cout << "Default constructor called" << std::endl;
}

Initializer list sets _fixedPoint to 0 — the only value this class can hold until ex01 adds real conversions. The print statement is the only way to prove, from the program's own output, that this constructor actually ran.

Fixed.cpp copy constructor

Fixed::Fixed(const Fixed &other) : _fixedPoint(other._fixedPoint) {
    std::cout << "Copy constructor called" << std::endl;
}

Builds a brand-new Fixed from an existing one. Only ever runs once, at the exact moment an object like Fixed b(a) is born — never again after that for the same object.

Fixed.cpp copy assignment operator

Fixed &Fixed::operator=(const Fixed &other) {
    std::cout << "Copy assignment operator called" << std::endl;
    if (this == &other) // guard against self-assignment (a = a)
        return *this;
    _fixedPoint = other._fixedPoint;
    return *this; // return *this so chains work: a = b = c
}

Different job from the copy constructor: this one overwrites an already-existing object's value. Returns Fixed& so assignments can chain (a = b = c;), and guards against a = a; before touching anything.

Fixed.cpp destructor, getRawBits, setRawBits

Fixed::~Fixed() { std::cout << "Destructor called" << std::endl; }

int Fixed::getRawBits(void) const {
    std::cout << "getRawBits member function called" << std::endl;
    return _fixedPoint;
}

void Fixed::setRawBits(int const raw) { _fixedPoint = raw; }

Nothing to release in the destructor — _fixedPoint is a plain int, so an empty body plus the print statement is the fully correct implementation.

main.cpp tests

int main(void) {
    Fixed a;    // default constructor
    Fixed b(a); // copy constructor
    Fixed c;    // default constructor
    c = b;      // copy assignment operator
    std::cout << a.getRawBits() << std::endl;
    std::cout << b.getRawBits() << std::endl;
    std::cout << c.getRawBits() << std::endl;
    return 0;
}

Questions to expect

Why does Fixed b(a) call the copy constructor and not copy assignment?
b doesn't exist before that line runs. C++ has to build it from scratch using a's value, and building a new object from an existing one is exactly the copy constructor's job. c = b is different: c already exists from the line above, so that's assignment overwriting it, not construction.
Why write all four canonical members if the compiler already generates them for free?
For a class holding one plain int, the compiler's automatic versions would actually work fine. The habit matters because the moment a class owns something like a heap pointer, the automatic version just copies the address, not the data — two objects end up sharing one resource, and the first one destroyed frees memory the second still thinks it owns. Writing all four explicitly now is the discipline that prevents that bug once it's actually possible.
Why is fractionalBits static?
static means there's exactly one copy shared by every Fixed object, not one per instance. It belongs to the class itself, not to any particular object — which makes sense since the scale factor never changes between objects.
Why is the self-assignment guard in operator= there — what would break without it?
For this class specifically, nothing would actually break, since there's no resource to free before copying. I included it anyway because it's the correct shape for a copy assignment operator in general — the day a class does own a resource, skipping that check causes it to free its own data right before trying to read from itself.
Important
Are all four canonical members present, with correct signatures, split between .hpp and .cpp?
Yes — default constructor, copy constructor, copy assignment operator (returning Fixed&), and destructor, all declared in Fixed.hpp and defined in Fixed.cpp, none implemented inline in the header.
Does getRawBits/setRawBits match the exact required signature?
Yes — int getRawBits(void) const; and void setRawBits(int const raw); — getRawBits is const since it only reads, setRawBits is not const since it modifies.
Do the print statements make it possible to verify which constructor or operator ran on each line?
Yes — running main prints Default, Copy constructor, Default, Copy assignment in that exact order, matching the four lines of the test one-to-one.
ex01

Towards a more useful fixed-point number class

Two converting constructors turn an int or float into raw bits; toInt/toFloat undo that; operator<< makes the whole thing printable.

New concepts this exercise introduces
converting constructors
Fixed(const int) and Fixed(const float) — same class, two more entry points, picked automatically based on the argument's type.
bit shift as multiply/divide
num << fractionalBits is exact — same as num × 256, at the bit level, no rounding.
free function operator<<
Can't be a member — Fixed would have to sit on the left of <<, and the whole point is std::cout on the left.

The pitch

"ex00's Fixed could only ever be 0 — this one can represent any int or float. Two new constructors convert into the raw representation, toFloat/toInt convert back out, and operator<< means I can just write std::cout << a instead of manually calling toFloat every time."

Walk the code

Fixed.cpp int and float constructors

Fixed::Fixed(const int num) : _fixedPoint(num << fractionalBits) {
    std::cout << "Int constructor called" << std::endl;
}
Fixed::Fixed(const float num)
    : _fixedPoint(roundf(num * (1 << fractionalBits))) {
    std::cout << "Float constructor called" << std::endl;
}

The int version shifts — exact, no rounding needed. The float version multiplies then rounds to the nearest whole number before storing in _fixedPoint. roundf is explicitly authorized for exactly this reason.

Fixed.cpp toFloat, toInt, operator<<

float Fixed::toFloat(void) const {
    return static_cast<float>(_fixedPoint) / (1 << fractionalBits);
}
int Fixed::toInt(void) const { return _fixedPoint >> fractionalBits; }

std::ostream &operator<<(std::ostream &stream, const Fixed &fix) {
    stream << fix.toFloat();
    return stream; // return stream so << chains: cout << a << b << endl
}

Questions to expect

Why does the int constructor shift, but the float constructor multiply?
Shifting only makes sense for a type whose bits directly encode value times a power of 2 — that's exactly what an int is. A float encodes numbers completely differently (mantissa and exponent), so there's no shift that could scale it. Multiplying achieves the same scaling through arithmetic instead of bit manipulation.
Why can't operator<< be a member function of Fixed?
A member function's implicit first parameter is always the object it's called on — the left side. If operator<< were a member, the only working syntax would be a << std::cout, Fixed on the left. Since the goal is std::cout << a, it has to be a free function taking the stream as its first explicit parameter.
Why does static_cast<float> have to come before the division in toFloat()?
Without it, _fixedPoint / (1 << fractionalBits) is int divided by int — plain integer division, which truncates before a float ever enters the picture. Casting the numerator first forces real floating-point division so the fractional part survives.
Important
Do the int and float constructors produce the correct raw value?
Yes — Fixed(10) raw = 2560 (10 << 8), Fixed(3.14f) raw = 804 (roundf(3.14 × 256)), both verifiable with getRawBits().
Is operator<< a free function, not a member, printing via toFloat()?
Yes — declared outside the class in Fixed.hpp, defined outside in Fixed.cpp, first parameter is std::ostream&.
ex02

Now we're talking

Six comparison operators, four arithmetic operators, four increment/decrement operators, and static min/max — the Fixed class becomes fully usable.

New concepts this exercise introduces
operator overloading
Writing member functions named operator+, operator>, etc. — the compiler calls them automatically when it sees the symbol with a Fixed operand.
why + works on raw bits but * does not
Adding two scaled values produces a correctly scaled result. Multiplying doubles the scale factor — so * and / convert to float first.
pre vs post increment
Pre returns a reference to self after modifying. Post saves a copy first, modifies self, then returns the old copy by value — must be by value since the copy is a local variable.
static member function
No implicit this — belongs to the class, not any instance. Called as Fixed::min(a, b), not a.min(b). Two overloads: one for mutable refs, one for const refs.
const overload
const Fixed & in, const Fixed & out. The compiler picks the right overload based on whether the arguments are const or not.

The pitch

"ex02 finishes the class — I add all the operators so Fixed behaves like a real numeric type. The interesting design decisions are why raw bits work for + and - but not for * and /, and why post-increment has to return by value instead of by reference."

Walk the code

Fixed.hpp complete header

class Fixed {
private:
    int _fixedPoint;                     // raw scaled value: real value × 256
    static const int fractionalBits = 8; // scale factor = 2^8 = 256
public:
    Fixed(void);
    Fixed(const int num);
    Fixed(const float num);
    Fixed(const Fixed &other);
    Fixed &operator=(const Fixed &other);
    ~Fixed();

    float toFloat(void) const;
    int   toInt(void) const;
    int   getRawBits(void) const;
    void  setRawBits(int const raw);

    // comparison — raw bits share same scale so order is preserved
    bool operator>(const Fixed &other) const;
    bool operator<(const Fixed &other) const;
    bool operator>=(const Fixed &other) const;
    bool operator<=(const Fixed &other) const;
    bool operator==(const Fixed &other) const;
    bool operator!=(const Fixed &other) const;

    // + and - work on raw bits; * and / convert to float first (raw*raw double-scales)
    Fixed operator+(const Fixed &other) const;
    Fixed operator-(const Fixed &other) const;
    Fixed operator*(const Fixed &other) const;
    Fixed operator/(const Fixed &other) const;

    Fixed &operator++();   // pre-increment  ++a — modify then return *this
    Fixed  operator++(int); // post-increment a++ — save copy, modify, return old by value
    Fixed &operator--();   // pre-decrement  --a — modify then return *this
    Fixed  operator--(int); // post-decrement a-- — save copy, modify, return old by value

    // static — no implicit this, called as Fixed::min(a, b)
    static Fixed &min(Fixed &a, Fixed &b);
    static const Fixed &min(const Fixed &a, const Fixed &b);
    static Fixed &max(Fixed &a, Fixed &b);
    static const Fixed &max(const Fixed &a, const Fixed &b);
};
// free function — Fixed must be on the right of <<, cannot be a member
std::ostream &operator<<(std::ostream &stream, const Fixed &fix);

Fixed.cpp comparison operators

// all six compare _fixedPoint directly — same scale factor, order preserved
bool Fixed::operator>(const Fixed &other) const { return _fixedPoint >  other._fixedPoint; }
bool Fixed::operator<(const Fixed &other) const { return _fixedPoint <  other._fixedPoint; }
bool Fixed::operator>=(const Fixed &other) const { return _fixedPoint >= other._fixedPoint; }
bool Fixed::operator<=(const Fixed &other) const { return _fixedPoint <= other._fixedPoint; }
bool Fixed::operator==(const Fixed &other) const { return _fixedPoint == other._fixedPoint; }
bool Fixed::operator!=(const Fixed &other) const { return _fixedPoint != other._fixedPoint; }

No conversion to float needed. Both sides were scaled by the same factor (256). Multiplying two numbers by the same constant preserves their order — 5 > 3 is still true after both become 1280 > 768.

Fig 1 — comparison works on raw bits because both sides share the same scale factor (256)

Fixed.cpp arithmetic operators

// + and - : raw bits, same scale survives
Fixed Fixed::operator+(const Fixed &other) const {
    Fixed result;
    result.setRawBits(_fixedPoint + other._fixedPoint);
    return result;
}
Fixed Fixed::operator-(const Fixed &other) const {
    Fixed result;
    result.setRawBits(_fixedPoint - other._fixedPoint);
    return result;
}
// * and / : convert to float — raw * raw double-scales
Fixed Fixed::operator*(const Fixed &other) const {
    return Fixed(this->toFloat() * other.toFloat());
}
Fixed Fixed::operator/(const Fixed &other) const {
    return Fixed(this->toFloat() / other.toFloat());
}

The split is intentional. Adding two scaled values keeps the scale intact. Multiplying does not — the scale factor gets applied twice, producing a result 256× too large. Division cancels the scale entirely. Both must go through float first.

Fig 2 — addition keeps the scale factor once; multiplication would apply it twice, so * and / go through float

Fixed.cpp increment / decrement

// pre: modify self, return reference to self — no copy
Fixed &Fixed::operator++() { _fixedPoint += 1; return *this; }
Fixed &Fixed::operator--() { _fixedPoint -= 1; return *this; }

// post: save old state, modify self, return old BY VALUE
// must return by value — old is a local variable, returning a ref to it = dangling ref
Fixed Fixed::operator++(int) { Fixed old = *this; _fixedPoint += 1; return old; }
Fixed Fixed::operator--(int) { Fixed old = *this; _fixedPoint -= 1; return old; }

Step size is 1 raw bit = 1/256 ≈ 0.00390625 — the smallest representable ε with 8 fractional bits. The int dummy parameter in the post-increment signature is how the compiler tells pre from post apart — it's never actually used inside the function.

Fig 3 — pre-increment returns a reference to self (modified); post-increment returns the old state by value

Fixed.cpp static min / max

// non-const overload — mutable objects, mutable ref returned
Fixed &Fixed::min(Fixed &a, Fixed &b) {
    if (a < b) return a; return b;
}
// const overload — const objects, const ref returned (compiler picks based on argument type)
const Fixed &Fixed::min(const Fixed &a, const Fixed &b) {
    if (a < b) return a; return b;
}
Fixed &Fixed::max(Fixed &a, Fixed &b) {
    if (a > b) return a; return b;
}
const Fixed &Fixed::max(const Fixed &a, const Fixed &b) {
    if (a > b) return a; return b;
}

static removes the implicit this — there is no "owner" object that makes sense for a function comparing two independent inputs. Returns a reference directly to whichever argument wins, so no copy is made and the caller can even modify the result.

Fig 4 — two overloads: compiler picks const or non-const based on the arguments passed in

main.cpp subject test

int main(void) {
    Fixed a;
    Fixed const b(Fixed(5.05f) * Fixed(2)); // float ctor, int ctor, *, copy ctor — all in one line

    std::cout << a << std::endl;   // 0
    std::cout << ++a << std::endl; // 0.00390625  (pre: a is now 1 raw bit)
    std::cout << a << std::endl;   // 0.00390625  (a still 1 raw bit)
    std::cout << a++ << std::endl; // 0.00390625  (post: returns OLD value, a goes to 2)
    std::cout << a << std::endl;   // 0.0078125   (a is now 2 raw bits)
    std::cout << b << std::endl;   // 10.1016     (5.05 * 2 = 10.1)
    std::cout << Fixed::max(a, b) << std::endl; // 10.1016  (b wins)
    return 0;
}

The line Fixed const b(Fixed(5.05f) * Fixed(2)) is worth tracing for the evaluator: Fixed(5.05f) calls the float constructor, Fixed(2) calls the int constructor, * calls your operator* (via float conversion), and the result initializes b via the copy constructor. Four different members on one line.

Questions to expect

Why do + and - work on raw bits but * and / do not?
Adding two scaled values: (5×256) + (3×256) = (8×256) — the scale factor stays once. Multiplying: (2×256) × (3×256) = 6×256×256 — the factor is applied twice, result is 256× too large. So * and / convert both sides to float, do the operation in real numbers, then construct a new Fixed from the result.
Why does post-increment return by value but pre-increment returns by reference?
Pre-increment modifies self and returns *this — a reference to the actual object, no copy. Post-increment saves a copy of the old state into a local variable called old, then modifies self, then returns old. But old lives on the stack inside the function — returning a reference to it would be a dangling reference to destroyed memory. The only safe option is to return a full copy by value.
What does the int dummy parameter in operator++(int) actually do?
Nothing — it's never used inside the function. It's just the compiler's convention for distinguishing post-increment from pre-increment. Pre has no parameter, post has a dummy int. Same for decrement.
Why are min and max static?
A normal member function has an implicit this — it belongs to one specific object. But min and max take two independent objects and compare them — there is no logical owner. static removes the implicit this so the call is Fixed::min(a, b) instead of the awkward a.min(a, b) where a appears twice.
Why are there two overloads of min and max instead of one?
The return type must match what goes in. If you pass const objects, you must get a const reference back — the compiler won't let you return a non-const reference to something declared const. So there are two overloads: one for regular mutable objects returning Fixed&, one for const objects returning const Fixed&. The compiler picks automatically based on what you pass.
What is epsilon here and why is the step size 1/256?
Epsilon is the smallest step the class can represent — one raw bit. Since the scale factor is 256, one raw bit corresponds to 1/256 ≈ 0.00390625 in real value. That's why ++a on a zero-initialized Fixed prints 0.00390625, not 1.
Important — evaluation checklist
Are all 6 comparison operators present and do they compare raw bits directly?
Yes — all six (>, <, >=, <=, ==, !=) compare _fixedPoint directly with the matching C++ operator. No toFloat() conversion needed.
Are + and - implemented on raw bits, and * and / implemented via float conversion?
Yes — + and - use setRawBits(_fixedPoint ± other._fixedPoint). * and / call toFloat() on both sides, operate, and pass the float result to Fixed's float constructor.
Are all four increment/decrement operators present? Do pre return Fixed& and post return Fixed (by value)?
Yes — operator++() and operator--() return Fixed& (reference to self). operator++(int) and operator--(int) return Fixed (by value, copy of old state).
Are both min and max present with two overloads each (mutable and const)?
Yes — four static functions total: Fixed& min(Fixed&, Fixed&), const Fixed& min(const Fixed&, const Fixed&), and the same pair for max.
Does the subject's own main produce the correct 7-line output?
Yes — 0 / 0.00390625 / 0.00390625 / 0.00390625 / 0.0078125 / 10.1016 / 10.1016, in that exact order.
